# Agent Memory System V3.0 - 长时间运行测试套件

本目录包含8个长时间、特复杂、高难度的真实实践测试场景，用于验证Agent Memory System V3.0在极端条件下的稳定性、可靠性和性能表现。

## 测试场景概览

| 场景 | 名称 | 运行时间 | 数据量 | 并发数 | 故障类型 |
|------|------|----------|--------|--------|----------|
| 1 | 24小时高负载Soak测试 | 10分钟(模拟24小时) | 100万条记忆 | 100客户端 | 延迟/错误/内存压力 |
| 2 | 极端并发写入风暴 | 10分钟(模拟30分钟) | 100万条记忆 | 1000客户端 | 网络延迟/写入超时/部分失败 |
| 3 | 级联故障恢复测试 | 10分钟(模拟20分钟) | 100万条记忆 | 100客户端 | Leader故障/Follower故障/网络分区 |
| 4 | 内存压力与OOM测试 | 10分钟(模拟15分钟) | 100万条记忆 | 100客户端 | 内存尖峰/GC压力/内存碎片 |
| 5 | 磁盘故障与数据损坏 | 10分钟(模拟20分钟) | 100万条记忆 | 100客户端 | 磁盘满/数据损坏/校验和不匹配 |
| 6 | 时钟漂移与分布式一致性 | 10分钟(模拟20分钟) | 100万条记忆 | 100客户端 | 时钟漂移/时间戳冲突/向量时钟分歧 |
| 7 | 网络分区脑裂测试 | 10分钟(模拟20分钟) | 100万条记忆 | 100客户端 | 网络分区/脑裂/数据分歧 |
| 8 | 完整灾难恢复演练 | 10分钟(模拟25分钟) | 100万条记忆 | 100客户端 | 数据中心故障/RPO/RTO验证 |

## 快速开始

### 运行所有测试场景

```bash
cd /workspace/agent_memory_system_v2/tests/long_running
python3 run_long_running_tests.py --all
```

### 运行单个场景

```bash
# 运行场景1: 24小时高负载Soak测试
python3 run_long_running_tests.py --scenario 1

# 运行场景2: 极端并发写入风暴
python3 run_long_running_tests.py --scenario 2
```

### 并行运行所有场景

```bash
python3 run_long_running_tests.py --parallel --duration 5
```

### 自定义运行时间

```bash
# 每个场景运行15分钟
python3 run_long_running_tests.py --all --duration 15
```

## 测试脚本说明

### 场景1: 24小时高负载Soak测试 (scenario1_soak_test.py)

**测试目标:**
- 持续写入/读取/查询操作
- 模拟100万条记忆的完整生命周期
- 监控内存泄漏、性能衰减
- 每10分钟检查一次系统健康

**关键指标:**
- 内存泄漏检测
- 性能衰减率
- 操作成功率
- GC统计

### 场景2: 极端并发写入风暴 (scenario2_write_storm.py)

**测试目标:**
- 1000个并发客户端同时写入
- 每秒10000次写入操作
- 持续30分钟
- 验证数据一致性和去重

**关键指标:**
- 实际TPS vs 目标TPS
- 去重率
- 写入延迟(P50/P99)
- 数据一致性违规

### 场景3: 级联故障恢复测试 (scenario3_cascading_failure.py)

**测试目标:**
- 5节点Raft集群
- 依次杀死Leader、Follower
- 网络分区 + 节点重启
- 验证自动恢复和数据完整性

**关键指标:**
- 故障注入总数
- 自动恢复成功率
- 选举次数
- 平均恢复时间

### 场景4: 内存压力与OOM测试 (scenario4_memory_pressure.py)

**测试目标:**
- 限制容器内存为512MB
- 持续加载大量数据
- 触发GC压力
- 验证优雅降级和恢复

**关键指标:**
- OOM事件数
- GC次数和耗时
- 优雅降级次数
- 压缩模式激活

### 场景5: 磁盘故障与数据损坏 (scenario5_disk_failure.py)

**测试目标:**
- 模拟磁盘满、磁盘损坏
- 随机数据损坏注入
- 验证数据校验和恢复
- 测试备份恢复流程

**关键指标:**
- 数据损坏检测率
- 数据修复成功率
- 备份操作成功率
- 校验和失败次数

### 场景6: 时钟漂移与分布式一致性 (scenario6_clock_drift.py)

**测试目标:**
- 各节点时钟不同步(±5秒)
- 验证分布式事务一致性
- 测试时间戳冲突解决
- 验证因果一致性

**关键指标:**
- 时间戳冲突数
- 向量时钟分歧
- 事务提交率
- 因果一致性违规

### 场景7: 网络分区脑裂测试 (scenario7_network_partition.py)

**测试目标:**
- 将集群分为两个分区
- 各自选举Leader
- 恢复分区后验证数据合并
- 测试冲突解决策略

**关键指标:**
- 脑裂事件数
- 数据分歧检测
- 冲突解决成功率
- 合并操作成功率

### 场景8: 完整灾难恢复演练 (scenario8_disaster_recovery.py)

**测试目标:**
- 模拟数据中心完全故障
- 从备份恢复
- 验证RPO/RTO指标
- 测试多区域故障转移

**关键指标:**
- RPO (恢复点目标) 达标率
- RTO (恢复时间目标) 达标率
- 数据丢失率
- 故障转移成功率

## 测试报告

每个测试场景运行后会生成以下报告文件:

- `{scenario}_report.json` - 详细的JSON格式测试报告

统一运行脚本会生成:

- `test_suite_report.json` - 测试套件整体报告
- `test_suite_report.html` - 可视化HTML报告
- `test_execution.log` - 测试执行日志

### 故障注入机制

每个测试场景都包含3种以上的故障注入:

1. **延迟故障** - 模拟网络延迟、处理延迟
2. **错误故障** - 模拟随机操作失败
3. **资源压力** - 模拟CPU、内存、磁盘压力

## 系统要求

- Python 3.8+
- 内存: 建议4GB+
- 磁盘: 建议10GB+可用空间
- 依赖: psutil, asyncio

## 安装依赖

```bash
pip install psutil
```

## 注意事项

1. **运行时间**: 每个场景默认运行10分钟, 完整测试套件约需80分钟(串行)或10分钟(并行)
2. **资源消耗**: 测试会消耗大量CPU和内存资源, 建议在专用测试环境运行
3. **日志文件**: 测试会生成大量日志, 请确保磁盘空间充足
4. **并发运行**: 并行运行会同时占用更多资源, 请根据系统配置调整

## 故障排查

### 测试失败常见原因

1. **内存不足** - 增加系统内存或减少并发客户端数
2. **磁盘空间不足** - 清理临时文件或增加磁盘空间
3. **权限问题** - 确保有写入日志和报告文件的权限
4. **依赖缺失** - 安装所需的Python依赖包

### 日志查看

```bash
# 查看执行日志
tail -f /workspace/agent_memory_system_v2/tests/long_running/test_execution.log

# 查看特定场景日志
tail -f /workspace/agent_memory_system_v2/tests/long_running/scenario1_soak_test.log
```

## 扩展开发

如需添加新的测试场景:

1. 复制现有场景脚本作为模板
2. 修改场景名称、描述和测试逻辑
3. 在 `run_long_running_tests.py` 中的 `TEST_SCENARIOS` 列表添加新场景
4. 确保新场景生成JSON格式的测试报告
